Класс вместо record: что Java пишет за тебя

Ты перепишешь Payment обычным классом и своими руками напишешь всё, что record генерировал молча. После этого станет понятно, почему геттер вызывается со скобками, что на самом деле значит static и почему в Java нельзя сравнивать объекты через ==.

Зачем это

В рабочем сервисе около 900 файлов, и большинство из них — классы: контроллеры, сервисы, сущности, DTO. Прочитать любой из них — значит узнать четыре части: поля, конструктор, методы и static-члены. Record прячет их за одной строкой, а обычный класс показывает целиком.

Шаг 1. Программа

В песочнице ~/Projects/java-sandbox создай Payments.java и, как и в прошлый раз, перепечатай код руками:

import java.math.BigDecimal;

public class Payments {

    record PaymentRecord(String account, BigDecimal amount) {}

    static class PaymentClass {
        private static int created = 0;

        private final String account;
        private final BigDecimal amount;

        PaymentClass(String account, BigDecimal amount) {
            this.account = account;
            this.amount = amount;
            created++;
        }

        String getAccount() {
            return account;
        }

        BigDecimal getAmount() {
            return amount;
        }

        static int created() {
            return created;
        }
    }

    public static void main(String[] args) {
        var r1 = new PaymentRecord("acc-1", new BigDecimal("10.50"));
        var r2 = new PaymentRecord("acc-1", new BigDecimal("10.50"));
        System.out.println("record equals: " + r1.equals(r2));
        System.out.println("record ==:     " + (r1 == r2));

        var c1 = new PaymentClass("acc-1", new BigDecimal("10.50"));
        var c2 = new PaymentClass("acc-1", new BigDecimal("10.50"));
        System.out.println("class equals:  " + c1.equals(c2));
        System.out.println("class print:   " + c1);
        System.out.println("created:       " + PaymentClass.created());
    }
}

java Payments.java выведет следующее (хеш после @ у тебя будет другим):

record equals: true
record ==:     false
class equals:  false
class print:   Payments$PaymentClass@2ea6137
created:       2

Анатомия класса

ЧастьЧто это и сравнение с TypeScript
private final String account;Поле. private — доступно только изнутри класса, final — присваивается один раз, в конструкторе. В TS это private readonly account: string. Record делает свои поля именно такими.
PaymentClass(String account, …) { this.account = account; }Конструктор: называется так же, как класс, и не имеет возвращаемого типа. Аналог в TS — constructor(…). Сокращения constructor(private readonly account: string), как в TS, в Java нет: поле объявляется и присваивается отдельно.
String getAccount() { return account; }Геттер — обычный метод. Свойств, как в TS (get account(), которое читается как поле), в Java нет. Отсюда скобки. Имя getX — соглашение JavaBeans, по нему Jackson превращает объект в JSON, а Spring связывает свойства. Record использует короткое имя: account().
private static int createdПоле класса, а не объекта: одна переменная на всех. Два new — два разных account, но created один, и он равен 2. В TS — static так же.
static int created()Метод класса: вызывается как PaymentClass.created(), без объекта. Поэтому внутри него нет this, и до account он не дотянется.

Шаг 2. Убери static у класса

Замени static class PaymentClass на class PaymentClass и запусти:

Payments.java:38: error: non-static variable this cannot be referenced from a static context
        var c1 = new PaymentClass("acc-1", new BigDecimal("10.50"));

Вложенный класс без static — это внутренний класс: каждый его объект привязан к объекту внешнего класса Payments. У статического метода main такого объекта нет, поэтому new не скомпилируется [dev.java: Nested Classes]. Record из урока 1 этим не страдал: вложенный record неявно статический. Верни static.

Шаг 3. Научи класс сравниваться

== на объектах сравнивает ссылки — «это один и тот же объект?». В TS === на объектах работает так же. Сравнение «по смыслу» в Java делает метод equals. Но если его не написать, класс унаследует версию от Object, а она тоже сравнивает ссылки [Object.equals]. Отсюда class equals: false. Record пишет equals по полям сам.

Задание. Допиши в PaymentClass три метода, чтобы его вывод совпал с выводом record: class equals: true и class print: PaymentClass[account=acc-1, amount=10.50].

  • public boolean equals(Object o) — равны, если совпадают оба поля;
  • public int hashCode() — обязан давать одинаковое число для равных объектов. Иначе HashMap и HashSet «потеряют» объект. Возьми Objects.hash(account, amount) из java.util.Objects;
  • public String toString().

Над каждым поставь аннотацию @Override. Это просьба к компилятору проверить, что ты действительно переопределяешь метод родителя, а не создаёшь новый с опечаткой в имени. Аннотации — первый шаг к Spring: там почти всё ими и объявляется.

Подсказка: проверка типа в equals

if (!(o instanceof PaymentClass other)) return false; проверяет тип и сразу заводит переменную other нужного типа [JEP 394]. Похоже на type guard в TS.

Решение (сначала попробуй сам) 
import java.util.Objects;   // в начало файла

        @Override
        public boolean equals(Object o) {
            if (this == o) return true;
            if (!(o instanceof PaymentClass other)) return false;
            return account.equals(other.account) && amount.equals(other.amount);
        }

        @Override
        public int hashCode() {
            return Objects.hash(account, amount);
        }

        @Override
        public String toString() {
            return "PaymentClass[account=" + account + ", amount=" + amount + "]";
        }

Около 20 строк на то, что record даёт одной строкой. Именно поэтому в Kotlin есть data class, а в Java-проектах часто используют Lombok. Обоим будет свой урок.

Шаг 4. Ловушка для денег

Добавь в конец main:

System.out.println(new BigDecimal("10.5").equals(new BigDecimal("10.50")));
System.out.println(new BigDecimal("10.5").compareTo(new BigDecimal("10.50")));

Получится false и 0. equals у BigDecimal учитывает и масштаб — количество знаков после точки, — а compareTo сравнивает только значение (0 значит «равны») [BigDecimal.equals]. Суммы денег сравнивают через compareTo. Заметь, что наш PaymentClass.equals (как и record) этим тоже грешит: платежи на 10.5 и 10.50 для него разные.

В рабочем коде тебя будут тормозить сигнатуры: тип стоит не там, где ты привык. Выбери TS-эквивалент Java-объявления. Клавиши: 1–3 — выбрать, Enter — дальше. Тренажёр живёт и на странице навыка «Чтение Java-сигнатур»: возвращайся к нему, пока не будешь проходить все 10 с первой попытки.
