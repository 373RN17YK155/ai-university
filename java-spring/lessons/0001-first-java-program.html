Первая программа на Java 17

После этого урока на твоём Mac будет тот же JDK, что в рабочем Docker-образе. Ты запустишь программу, которая считает платежи, и разберёшь свою первую ошибку компилятора.

Зачем это

Рабочий сервис собран на Java 17 и работает в образе amazoncorretto:17. На твоей машине сейчас стоит только JDK 8, а в нём нет ни record, ни var, и он не умеет запускать .java-файл напрямую. Поэтому начинаем с того же дистрибутива, что в продакшене: Amazon Corretto 17.

Шаг 1. Поставить JDK 17

  1. Установи Corretto 17 через Homebrew: 
    brew install --cask corretto@17
  2. Посмотри, какие JDK теперь есть. Должны быть и 1.8, и 17: 
    /usr/libexec/java_home -V
  3. Сделай 17-ю версией по умолчанию: добавь в ~/.zshrc строку 
    export JAVA_HOME=$(/usr/libexec/java_home -v 17)
    открой новый терминал и проверь: java -version должен начинаться с openjdk version "17.0.…" и упоминать Corretto.

Шаг 2. Программа

Создай папку-песочницу вне этого репозитория, например ~/Projects/java-sandbox, и в ней файл Hello.java. Перепечатай код руками, а не копируй: так синтаксис запоминается лучше.

import java.math.BigDecimal;
import java.util.List;

public class Hello {

    record Payment(String account, BigDecimal amount) {}

    static BigDecimal total(List<Payment> payments) {
        BigDecimal sum = BigDecimal.ZERO;
        for (Payment p : payments) {
            sum = sum.add(p.amount());
        }
        return sum;
    }

    public static void main(String[] args) {
        var payments = List.of(
            new Payment("acc-1", new BigDecimal("10.50")),
            new Payment("acc-2", new BigDecimal("0.20"))
        );
        System.out.println(payments.get(0));
        System.out.println("Итого: " + total(payments));
        System.out.println(0.1 + 0.2);
    }
}

Запуск: java Hello.java. Начиная с Java 11 так можно запустить программу из одного файла без отдельной компиляции: JDK компилирует её в памяти и сразу выполняет [JEP 330]. Должно получиться:

Payment[account=acc-1, amount=10.50]
Итого: 10.70
0.30000000000000004

Что здесь происходит

СтрокаСмысл
public class HelloВ Java весь код живёт внутри классов. Публичный класс называется так же, как файл.
record Payment(…)Неизменяемый «носитель данных». Конструктор, методы account() и amount(), а также equals, hashCode и toString Java генерирует сама [JEP 395]. Именно так в Spring-сервисах часто выглядят DTO.
static BigDecimal total(List<Payment> …)У каждого параметра и возвращаемого значения есть тип, и компилятор проверяет его до запуска. List<Payment> — дженерик: список, в котором лежат только Payment.
public static void main(String[] args)Точка входа. static значит, что метод принадлежит классу, а не объекту, поэтому его можно вызвать, ничего не создавая.
var payments = …Тип локальной переменной выводит компилятор (здесь это List<Payment>), и дальше он не меняется. Это не динамическая типизация [JEP 286].
new BigDecimal("10.50")Десятичное число произвольной точности. Деньги считают в нём, а не в double: третья строка вывода показывает почему.

Шаг 3. Сломай

Замени new BigDecimal("0.20") на просто 0.20 и запусти снова. Программа даже не начнёт выполняться: Java проверяет типы при компиляции.

Hello.java:19: error: constructor Payment in record Payment cannot be applied to given types;
  required: String,BigDecimal
  found:    String,double
  reason: argument mismatch; double cannot be converted to BigDecimal

Читать такую ошибку стоит в таком порядке: файл:строка → required (что ожидалось) → found (что передали) → reason. Эти же четыре части будут в каждой второй ошибке компиляции в рабочем проекте, просто строк вокруг станет больше.

Верни BigDecimal на место.

Проверь себя

Отвечай по памяти, не подглядывая в текст выше: так знание закрепляется лучше.
